# 품질 기준 (quant 서비스)

모든 일감의 '다 됐다'와 검토는 이 문서를 기준으로 해요. 규칙에는 번호가 있어서, 검토 기록에 번호로 적어요(예: `S5 위반 · api/live.py:40`). 단계마다 적용 범위가 다르면 규칙 옆에 적었어요. 왜 이 기준인지는 `PRODUCT.md`, 코드 자리는 `ARCHITECTURE.md`예요. 재는 숫자(신뢰성 · 성능 · 접근성 등)는 `PRODUCT.md` 4절이 기준이에요(예: 20:10 회차가 다음 날 08:20 전에 끝남 · 화면 요청 p95 200ms 이하). 이 문서의 규칙이 `SPEC.md` · `ENGINE-RULES.md`의 동작과 다르면 그쪽이 이기고(1단계는 지금 동작 그대로 · 7절), 어긋남은 `OPEN-QUESTIONS.md` 4절에 적어요.

## 1. 보안

| 번호 | 규칙 | 확인 |
|---|---|---|
| S1 | 키 · 비밀번호 · 계좌번호 · 토큰은 설치한 기기의 앱 설정 폴더에만 둬요(데이터 폴더 밖 · 파일 권한 600). 화면에 다시 보일 때는 끝 4자리만 보여요 | 키 파일 위치 · 권한 시험 |
| S2 | 기록 · 오류 글 · 예외 메시지 · API 응답에 비밀 값을 남기지 않아요. 가릴 이름 목록은 한 곳에 둬요 | 가림 시험 · 기록 검사 |
| S3 | 바깥 연결은 정해 둔 곳만 열어요(토스 · DART · 텔레그램 · AI 제공사 · 공인 IP 확인 · 사용자가 등록한 OpenAI 호환 주소). 허용 목록은 앱 안 한 곳에 둬요. 시험에서는 바깥 소켓이 0이에요 | `test_no_orders.py` · 소켓 검사 |
| S4 | 서버는 127.0.0.1에만 묶어요. Host · Origin 검사 · CSRF · SameSite=Strict · 세션 만료 · 로그인 5번 틀리면 잠금 | 보안 시험 묶음 |
| S5 | 돈이 움직이는 요청(주문 · 운용 시작 · 운용 원금 · 한도 · 운용 중단 · 키 변경 · 매수 · 매도 금지 변경)은 비밀번호를 다시 받아요. 검사는 서버에서 해요(화면만 믿지 않음) | 금고 흐름 시험 |
| S6 | 모든 API 입력은 스키마로 검사해요. 전략 글 · 파일은 형식 버전을 검사해요. 사용자 글을 코드로 실행하지 않아요(eval · exec · 템플릿 실행 0) | 시험 · 정적 검사 |
| S7 | 의존성은 정확한 버전으로 고정해요(lock · 해시). 새 의존성은 까닭 한 줄과 함께 더하고, 알려진 취약점 검사(pip-audit · npm audit)를 `product/service/app/scripts/check.sh`에 넣어요(1단계 P1-02부터 · 1단계는 판을 올리지 않고, 나온 취약점은 허용 목록과 OPEN-QUESTIONS로) | `check.sh` |
| S8 | AI로 보내는 글(4단계): 데이터는 '지시가 아닌 자료' 칸에 넣어요. 도구는 읽기 전용만 두고, 도구 인자는 앱 목록과 정확히 맞아야 해요. AI 답은 정해 둔 응답 형식으로만 받아요(형식 밖이면 실패 규칙). 키 · 계좌번호 · 다른 보유 종목은 보내지 않아요 | 숨은 지시 시험 |
| S9 | 주문 안전: 주문마다 앱 주문 번호를 두고, 보내기 전에 'sending'을 먼저 기록해 같은 주문을 두 번 보내지 않아요. 결과를 모르는 주문은 다시 보내지 않고 정해 둔 절차로 확인해요. 하루 주문 상한 · 분당 신규 매수 상한을 지켜요. 전송은 기본이 가짜예요 | 주문 기록 순서 시험 · `test_no_orders.py` |
| S10 | 백업 파일에 키를 넣지 않아요(복원 뒤 다시 입력). 복원하면 새 매수를 멈춘 채 시작해요 | 시험 |
| S11 | `check.sh`가 `product/` 아래 추적되는 파일에서 비밀 꼴 문자열을 찾아요: 키 · 토큰 꼴 · 계좌번호 꼴 · 공인 IP(127.0.0.1 · 사설 범위 · 문서용 범위는 뺌). 꼴은 거짓 경보가 적게 좁게 정해요. 생성 파일(`package-lock.json` · `vendor/` · 시험 자료)은 빼는 까닭을 적고, 지어낸 시험 값(`12345671234` 등)은 허용 목록에 까닭과 함께 둬요. 범위 밖인 레포 뿌리 운영 앱에서 본 것은 고치지 않고 OPEN-QUESTIONS 4절에 적어요(1단계 P1-02부터) | `check.sh` |
| S12 | 텔레그램으로 받는 명령은 등록한 대화방에서만 받아요. 할 수 있는 것은 새 매수 멈춤(`/멈춤` · `/stop`)과 상태(`/상태` · `/status`)뿐이고, 켜거나 사는 명령은 0이에요(`ENGINE-RULES.md` R-L9 · R-L13) | 명령 받기 시험 |
| S13 | 바깥에서 앱에 닿는 길은 Tailscale serve(내 기기끼리)뿐이에요. Funnel(공개 인터넷 노출)은 0이에요 | 설치 시험 |
| S14 | AI(4단계): 달 예산 · 호출당 상한을 앱이 지켜요. 넘거나 실패하면 AI 칸만 쉬어요. AI 답은 한도 · 매수 금지 · 보호 매도 검사를 건너뛰지 못해요 | 예산 시험 · 조합 시험(T2) |

## 2. 외부 연결 (토스 · DART · AI 제공사 · 텔레그램 · Tailscale)

E12 ~ E15는 2단계부터예요(1단계는 지금 동작 그대로).

| 번호 | 규칙 |
|---|---|
| E1 | 서비스마다 어댑터 하나가 모든 호출을 맡아요(포트 뒤). 다른 곳에서 HTTP · 소켓을 직접 열지 않아요 |
| E2 | 시간 초과를 호출 종류마다 정한 표 하나에 둬요. 끝없이 기다리는 호출은 0이에요 |
| E3 | 다시 시도는 결과가 바뀌지 않는 조회에만 해요(지수 백오프 + 지터 · 최대 횟수). 주문은 다시 보내지 않고 '결과 모르는 주문' 절차로 가요 |
| E4 | 요청 한도 예산을 서비스 · 그룹마다 한 표로 둬요(토스 1.2.28 그룹별 초당 한도 · DART 하루 20,000건 · 분당 1,000회). 보호 매도 몫을 먼저 남기고, 한도 응답(429)이 오면 그 그룹을 늦춰요. 응답 헤더 `X-RateLimit-Limit`로 예산을 고쳐요 |
| E5 | 연속 실패가 정한 횟수를 넘으면 그 연결을 '끊김'으로 두고 할 일 · 상태 칩에 보여요. 다시 붙는 규칙을 정해요. 웹소켓은 180초 무응답 전에 신호를 보내고, 끊기면 다시 구독해요 |
| E6 | 서비스 오류는 앱 오류 번호(인증 · 한도 · 입력 · 서버 · 결과 모름 · 연결)로 바꿔요. 화면에는 원인 한 줄과 다음 행동을 보여요 |
| E7 | 모든 시각은 한국 시간이고 `Clock` 포트로 받아요. 장 시간 · 휴장일 · 단일가 · 정리매매는 `domain/markets/kr.py` 한 곳에 둬요 |
| E8 | 받은 자료마다 기준 시각을 붙여요. 신선도 기준을 넘은 자료는 '늦음'으로 보이고, 그 자료를 쓰는 판단은 쉬어요 |
| E9 | 명세는 고정해요(토스 REST 1.2.28 · 웹소켓 1.2.2 · DART를 `vendor/`에). 가짜 응답은 명세에서 만들고, 명세가 바뀌면 시험이 알려요 |
| E10 | 어댑터마다 녹화한 응답(정상 · 한도 · 오류 · 끊김 · 늦은 응답)으로 계약 시험을 해요. 실제 서버는 부르지 않아요 |
| E11 | 토스 토큰은 클라이언트당 하나만 유효해요(새로 받으면 앞 토큰이 끊김). 앱 안 토큰 관리자 하나가 맡아요 |
| E12 | 받은 일봉을 검사해요. 빈 날 · 0원 · 급변 · 수정주가 단절이 있으면 그 종목 판단을 쉬고 기록해요 |
| E13 | 휴장일 표가 다음 해를 덮지 않으면 할 일로 알려요. 기기 시계가 기준 시각과 정한 값보다 많이 어긋나면 주문을 쉬어요 |
| E14 | 허용 IP 점검이 실패하면 `ENGINE-RULES.md` R-L3대로 해요(PC는 공인 IP가 바뀌면 할 일로 알림) |
| E15 | 모르는 응답 값(새 주문 상태 등)은 `ENGINE-RULES.md` R-O14와 '결과 모르는 주문' 절차를 따라요. 짐작으로 이어 가지 않아요 |

## 7. 검토 순서와 판정

검토는 그 일감을 만들지 않은 쪽이 커밋한 diff(`git show`)로 해요.
