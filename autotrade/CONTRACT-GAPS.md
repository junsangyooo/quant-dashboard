# 계약 공백 — 아직 열린 것

2026-10-09 API 세션이 정리했다. 화면 에이전트가 찾은 공백(자산·계획 6+3, 작동·모드·설정·입장 10, 기록·그날·규칙 18)은 CONTRACT.md에 반영했다(맨 아래 '바뀐 것'의 '계약 공백 정리' 세 줄). 여기에는 아직 정하지 못한 것과 API 밖에서 정할 것만 남긴다.

## 정할 것(API)
1. **헤더가 AI 규칙의 카드를 세지 않는다.** `/api/shell`의 상태는 지수 반반의 주문과 확인만 본다. 공시 감시가 멈춰도(빨강, 자동으로 다시 함) AI 일감이 세 번 실패해 사람을 기다려도(빨강, 직접 할 일) 헤더는 '정상'인데 작동 화면은 '점검'이다.
   - 제안: 직접 할 일 카드는 `status.todo`의 수에, 자동으로 다시 하는 빨간 카드는 `status.check`의 원인 수에 넣는다. 배너는 그대로 둔다.
   - 아직 안 한 이유: 헤더는 모든 화면에 걸린다. 넣으면 DART가 점검하는 시간마다 헤더가 '점검'으로 바뀐다.
2. **AI 판단의 `inputSummary`·`outputSummary`에 서버가 지은 한국어 조각이 있다**('유지 · 반증', '새 종목 3', '바꾼다'). 원칙('문구는 화면이 만든다')의 예외다.
   - 모델이 쓴 근거(120자까지)와 뉴스 출처·날짜는 데이터라 그대로 둘 수 있다. 서버가 지은 조각은 코드와 수로 바꿀 수 있다.
   - 아직 안 한 이유: 바꾸면 웹의 판단 카드도 같이 바뀐다(2단계에서 생긴 것).
3. **실적 발표일 예정 항목(`ScheduleItem.earnings`)**: 계약에 자리만 있고 보내지 않는다. 발표일을 미리 알려 주는 공개 자료원이 없다(DART·EDGAR는 공시가 나온 뒤에만 안다).

## API 밖(웹·디자인·유준상)
4. AI 판단 카드는 Figma 그림이 없다. 웹이 노드 카드 말투로 만들었다(칸 이름 '판단').
5. 디자인 시스템: Figma `flow/*` 변수 4개가 tokens.json에 없다(페이지 CSS에서 기존 토큰으로 매핑). 390 프레임의 옆 여백 16과 앱의 20이 다르다.
6. 예시 값표에 없는 숫자로 만든 고정 자료가 있다(7/1 주문가, 9/14 비중, 9/30 비중, 실전 수수료·월 변동, 끈 기간 9/21~9/25, 10/4 주말, AI 판단 10/2, 3년 발굴 흐름 값). 웹 세션의 예시 값표에 더할지 정한다.
7. 새로 지은 문구는 `web/src/copy/{pin,health,mode,account}.ts`에 NEW로 표시돼 있다. 유준상에게 한 번 보여 준다.
